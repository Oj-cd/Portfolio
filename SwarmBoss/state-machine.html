Swarm Boss · Unreal Engine 5 · C++

Four-State Boss Behavior

The swarm cycles through Idle, Rush, Regroup and Orbit. No state moves a unit directly. Each one only decides where the flock should want to go, and the Boids pass does the rest.

The Cycle

Every state has a steering target and an exit condition. All durations and distances are EditAnywhere under Swarm|States, so the fight is paced in the details panel rather than recompiled.

  • Idle: hovers around the core. Exits after IdleDuration, or early if the player comes within RushTriggerDistance.
  • Rush: steers straight at the player and fires a camera shake on entry. Exits after RushDuration.
  • Regroup: snaps back to the core with cohesion and max speed temporarily raised. Exits after RegroupDuration.
  • Orbit: circles the player at OrbitRadius, then loops back to Rush.
States Only Set a Target

Each state writes one value, CohesionTarget, and the flocking pass pulls every unit toward it. Movement lives in exactly one place, so a new state is a few lines rather than a new movement path.

Source/LDP/Private/SwarmManager.cpp ↗
void ASwarmManager::UpdateStateMachine(float DeltaTime)
{
    StateTimer += DeltaTime;

    // if the player gets too close during idle, rush immediately
    if (CurrentState == ESwarmState::Idle && PlayerActor)
    {
        float DistSquaredToPlayer = FVector::DistSquared(GetActorLocation(), PlayerActor->GetActorLocation());
        if (DistSquaredToPlayer < RushTriggerDistance * RushTriggerDistance)
        {
            EnterState(ESwarmState::Rush);
        }
    }

    switch (CurrentState)
    {
        case ESwarmState::Rush:
            CohesionTarget = PlayerActor ? PlayerActor->GetActorLocation() : GetActorLocation();

            if (StateTimer >= RushDuration)
            {
                EnterState(ESwarmState::Regroup);
            }
            break;

        case ESwarmState::Orbit:
        {
            if (PlayerActor)
            {
                // StateTimer keeps climbing, so feeding it into Cos/Sin traces a circle around the player
                float Angle = StateTimer * OrbitAngularSpeed;
                FVector PlayerLoc = PlayerActor->GetActorLocation();
                CohesionTarget = PlayerLoc + FVector(
                    FMath::Cos(Angle) * OrbitRadius,
                    FMath::Sin(Angle) * OrbitRadius,
                    0.f
                );
            }

            if (StateTimer >= OrbitDuration)
            {
                EnterState(ESwarmState::Rush);
            }
            break;
        }

        // Idle and Regroup follow the same shape, see the full source
    }
}

Why steer a target instead of the units? Because the swarm never teleports or snaps. When Rush ends and the target jumps back to the core, separation and alignment keep running, so the flock turns and streams home as a body instead of every unit reversing on the same frame.

One Way In

Every transition goes through EnterState. The timer reset and any on-enter effects live there, so no branch of the switch can forget them.

Source/LDP/Private/SwarmManager.cpp ↗
void ASwarmManager::EnterState(ESwarmState NewState)
{
    CurrentState = NewState;
    StateTimer = 0.f;

    if (NewState == ESwarmState::Rush)
    {
        TriggerRushCameraShake();
    }
}
  • Camera shake is a class, not an instance. RushCameraShake is a TSubclassOf<UCameraShakeBase> picked in the editor; the player controller spawns the actual shake when Rush begins, and the call is skipped cleanly if none is assigned.
  • Early rush uses a squared distance. The proximity check only needs a threshold, so it never pays for a square root.
Regroup Without Losing Tuning

Regroup needs the swarm to pull in harder and move faster than normal, which means temporarily overriding two designer-tuned values.

Restoring hardcoded values would erase tuning

Writing fixed defaults back at the end of Regroup would silently throw away whatever cohesion and speed had been set in the details panel after the first state cycle.

Fix: BeginPlay snapshots CohesionWeight and MaxSpeed into DefaultCohesionWeight and DefaultMaxSpeed. Regroup applies RegroupCohesionWeight and RegroupMaxSpeed, then restores the snapshot on exit, so every value set in the editor survives any number of cycles.
What I Would Change Next
  • Transitions run on timers. Driving them from what the player is doing (distance, remaining health, damage dealt recently) would make the fight read as reactive rather than scripted.
  • Movement ignores the world. Units steer in open space with no obstacle avoidance or navmesh awareness. That suits the arena it was built for but would not survive a cluttered level.
