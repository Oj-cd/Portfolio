Swarm Boss · Unreal Engine 5 · C++

Damage & Core Exposure

The swarm takes damage as one body through Unreal's standard damage pipeline, converts it into unit kills, and opens the core once enough of it is gone. Presentation hooks out to Blueprint so the simulation never has to know about it.

Damage Against a Crowd

Weapons call ApplyPointDamage like they would on any actor. TakeDamage pools the incoming damage and pays it out as kills at DamagePerKill each.

Source/LDP/Private/SwarmManager.cpp ↗
float ASwarmManager::TakeDamage(float DamageAmount, FDamageEvent const& DamageEvent,
    AController* EventInstigator, AActor* DamageCauser)
{
    float ActualDamage = Super::TakeDamage(DamageAmount, DamageEvent, EventInstigator, DamageCauser);

    if (ActualDamage <= 0.f || AliveUnitCount <= 0) return ActualDamage;

    // FPointDamageEvent carries the exact impact point, fall back to the actor location if it isn't one
    FVector HitLocation = GetActorLocation();
    if (DamageEvent.IsOfType(FPointDamageEvent::ClassID))
    {
        const FPointDamageEvent* PointDamage = static_cast<const FPointDamageEvent*>(&DamageEvent);
        HitLocation = PointDamage->HitInfo.ImpactPoint;
    }

    OnSwarmHit(ActualDamage, HitLocation);

    DamagePool += ActualDamage;

    AliveIndices.Reset();
    for (int32 i = 0; i < Units.Num(); i++)
    {
        if (Units[i].bIsAlive) AliveIndices.Add(i);
    }

    // while instead of if so a single big hit like an AOE can kill multiple units in one shot
    while (DamagePool >= DamagePerKill && AliveIndices.Num() > 0)
    {
        DamagePool -= DamagePerKill;

        // swapping the picked entry with the last one and popping is O(1)
        int32 PickedSlot = FMath::RandRange(0, AliveIndices.Num() - 1);
        int32 UnitIndex = AliveIndices[PickedSlot];
        AliveIndices.RemoveAtSwap(PickedSlot, 1, EAllowShrinking::No);

        KillUnit(UnitIndex);
    }

    return ActualDamage;
}
  • Leftover damage carries over. Anything under DamagePerKill stays in the pool for the next hit, so weak rapid-fire weapons still thin the swarm at the right rate.
  • Kills are random, removal is O(1). A random living unit is picked and removed from the candidate list with RemoveAtSwap instead of shifting the rest of the array down.
  • The cast is safe without Cast<>. IsOfType already confirmed the event type, and Cast<> only works on UObjects, which a damage event struct is not.

An AOE allocated an array per kill

The living-unit candidate list used to be rebuilt inside the kill loop, so one big area hit that took out dozens of units built dozens of arrays in a single frame.

Fix: build the list once per damage event, into a member array reserved at spawn, and remove from it as units die. Resolving any number of kills now allocates nothing.
Opening the Core

Once the swarm is thinned below CoreExposureFraction of its starting count, the core underneath becomes hittable.

Source/LDP/Private/SwarmManager.cpp ↗
void ASwarmManager::KillUnit(int32 UnitIndex)
{
    if (!Units.IsValidIndex(UnitIndex)) return;
    if (!Units[UnitIndex].bIsAlive) return;

    Units[UnitIndex].bIsAlive = false;
    AliveUnitCount--;

    int32 ExposureThreshold = FMath::FloorToInt(UnitCount * CoreExposureFraction);
    if (!bCoreExposed && AliveUnitCount <= ExposureThreshold)
    {
        bCoreExposed = true;

        if (CoreActor)
        {
            UPrimitiveComponent* CorePrimitive = Cast<UPrimitiveComponent>(CoreActor->GetRootComponent());
            if (CorePrimitive)
            {
                CorePrimitive->SetCollisionEnabled(ECollisionEnabled::QueryAndPhysics);
                CorePrimitive->SetCollisionResponseToAllChannels(ECR_Block);
            }
        }

        OnCoreExposed();
    }
}

The core sometimes never opened

The threshold check originally used ==. Single-target hits stepped the count down one at a time and hit it exactly, but an area hit that killed several units at once could step straight past the threshold, and the core stayed shut for the rest of the fight.

Fix: compare with <= and guard with bCoreExposed, so exposure fires on the first crossing no matter how big the step, and exactly once.
C++ Simulation, Blueprint Presentation

C++ owns the simulation. Everything the player sees or hears as a reaction is raised as an event and implemented in a Blueprint child.

Source/LDP/Public/SwarmManager.h ↗
// triggers from c++, implemented in the blueprint child so I can hook up floating damage text
UFUNCTION(BlueprintImplementableEvent, Category = "Swarm|Combat")
void OnSwarmHit(float DamageAmount, FVector HitLocation);

// triggers in blueprint when the core becomes exposed so I can swap material, play a sound etc
UFUNCTION(BlueprintImplementableEvent, Category = "Swarm|Combat")
void OnCoreExposed();
  • Every tuning value is exposed. Unit count, Boids weights, state timings, damage per kill and exposure fraction are all EditAnywhere, grouped under Swarm|Spawn, Boids, States, Combat and Feel. DamagePool is VisibleAnywhere so it can be watched live during play without being editable.
  • The swarm is a normal damage target. The instanced mesh is the root with WorldDynamic collision that blocks everything, so any weapon trace lands on it with no special-case code.

Constructor collision settings were overwritten

Setting the swarm to ignore the camera channel in the constructor did nothing at runtime. The Blueprint child serializes its own copy of the component's collision settings, and that copy is loaded over whatever the constructor set.

Fix: apply the camera ignore in BeginPlay, which runs after the Blueprint data is loaded, so the C++ setting always wins and the camera no longer collides with the swarm.
