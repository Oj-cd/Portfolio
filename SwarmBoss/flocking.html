Boids Flocking & Rendering

A hundred units that move as one boss, owned by a single actor, steered by two-pass Boids, and drawn in one draw call through an instanced static mesh.

One Actor, Not a Hundred

Spawning an AActor per unit would cost a tick, a transform hierarchy and a component registration each. Instead one ASwarmManager owns a flat array of plain structs.

  • Units are data, not objects. Each unit is location, velocity and an alive flag. Nothing else needs to exist per unit at runtime.
  • Arrays are sized once. SpawnUnits reserves the unit, transform and damage-candidate arrays upfront, so no array grows and copies itself mid-loop or mid-fight.
  • Movement stays flat. Vertical velocity is zeroed at spawn and every tick so the swarm reads as a cloud hugging the arena instead of drifting upward.
Source/LDP/Public/SwarmManager.h ↗
// holds everything I need to track per unit at runtime
USTRUCT()
struct FSwarmUnit
{
    GENERATED_BODY()

    FVector Location;
    FVector Velocity;
    bool bIsAlive = true;
};
Boids in Two Passes

The flock runs as two passes per tick. The first pass gathers group-wide stats, the second applies separation, alignment and cohesion to each unit against those stats.

Source/LDP/Private/SwarmManager.cpp ↗
void ASwarmManager::TickBoids(float DeltaTime)
{
    // first pass collects group wide stats so each unit can compare itself to the whole swarm
    FVector CenterOfMass = FVector::ZeroVector;
    FVector AverageVelocity = FVector::ZeroVector;
    int32 Count = 0;

    for (auto& Unit : Units)
    {
        if (!Unit.bIsAlive) continue;
        CenterOfMass += Unit.Location;
        AverageVelocity += Unit.Velocity;
        Count++;
    }

    if (Count == 0) return;

    CenterOfMass /= Count;
    AverageVelocity /= Count;

    // second pass applies the three boids rules to each unit using those stats
    for (auto& Unit : Units)
    {
        if (!Unit.bIsAlive) continue;

        FVector Separation = FVector::ZeroVector;
        FVector Alignment = AverageVelocity - Unit.Velocity; // steer toward group direction
        FVector Cohesion = CohesionTarget - Unit.Location;   // steer toward group center

        for (auto& Other : Units)
        {
            if (&Other == &Unit || !Other.bIsAlive) continue;

            FVector Diff = Unit.Location - Other.Location;

            // comparing squared distances first so a far away neighbor never pays for a square root
            float DistSquared = Diff.SizeSquared();
            if (DistSquared >= SeparationRadius * SeparationRadius || DistSquared <= 0.f) continue;

            float Dist = FMath::Sqrt(DistSquared);
            Separation += Diff.GetSafeNormal() * (1.0f - Dist / SeparationRadius);
        }

        Unit.Velocity += (Separation * SeparationWeight)
            + (Alignment * AlignmentWeight)
            + (Cohesion * CohesionWeight);

        // drag multiplier, without this velocity would compound forever
        Unit.Velocity *= VelocityDamping;

        if (Unit.Velocity.SizeSquared() > MaxSpeed * MaxSpeed)
            Unit.Velocity = Unit.Velocity.GetSafeNormal() * MaxSpeed;

        Unit.Velocity.Z = 0.f;
        Unit.Location += Unit.Velocity * DeltaTime;
    }
}

Why two passes? In a single pass, units early in the array would steer against last frame's picture of the swarm and units later in it against a half-updated one. Splitting the stats out means every unit reacts to the same snapshot, so the flock behaves the same regardless of array order.

Cohesion steers toward CohesionTarget, not the center of mass. That one variable is the hook the state machine uses to move the entire swarm without ever touching unit positions directly.

Separation Falloff

Separation is the only rule that looks at individual neighbors, and its falloff decides how the swarm feels up close.

Separation += Diff.GetSafeNormal() * (1.0f - Dist / SeparationRadius);

Textbook inverse-square blew units apart

The common version divides by distance squared. As two units approach the same point the push approaches infinity, and overlapping units launched each other out of the swarm.

Fix: a linear falloff of 1 - Dist / Radius. It is 1 at dead center and 0 at the edge of the radius, so close neighbors get a firm shove and distant ones barely feel it, with no spike near zero.
One Draw Call

The whole swarm is rendered by one UInstancedStaticMeshComponent. The simulation writes into a reused transform array and hands it to the renderer in a single batched update each frame.

Source/LDP/Private/SwarmManager.cpp ↗
void ASwarmManager::SyncInstances()
{
    for (int32 i = 0; i < Units.Num(); i++)
    {
        FTransform& T = InstanceTransforms[i];
        T = FTransform::Identity;

        if (!Units[i].bIsAlive)
        {
            // scale to zero instead of removing the instance, removing would shift every index after it
            T.SetScale3D(FVector::ZeroVector);
            continue;
        }

        T.SetLocation(Units[i].Location);
        T.SetScale3D(FVector(UnitScale));

        if (!Units[i].Velocity.IsNearlyZero())
            T.SetRotation(Units[i].Velocity.ToOrientationQuat());
    }

    // one batched call and one dirty mark, so the renderer rebuilds once per frame rather than per instance
    ISMComponent->BatchUpdateInstancesTransforms(0, InstanceTransforms, true, false, false);
    ISMComponent->MarkRenderStateDirty();
}
  • Dead units scale to zero. Removing an ISM instance shifts every index after it, which would silently break the one-to-one mapping between Units[i] and instance i.
  • Units face where they fly. Rotation comes from the velocity as a quaternion, skipped when velocity is near zero so a stalled unit does not snap to a default facing.
  • No per-frame allocation. InstanceTransforms is sized once in SpawnUnits and overwritten in place every frame.
Cost and Scaling

Rendering cost is flat regardless of unit count. The simulation is the real ceiling, and I know exactly where it is.

  • Separation is O(n²). Every unit checks every other unit. At the default 100 units that is about 10,000 comparisons per frame, which costs nothing, but it becomes the bottleneck long before rendering does.
  • Cheap mitigations are already in. Squared-distance rejection so most pairs never pay for a square root, early skips on dead units, and alignment and cohesion computed from swarm-wide averages in one O(n) pass instead of another neighbor sweep.
  • Next step: a spatial hash. Separation only cares about neighbors inside SeparationRadius, so bucketing units into a uniform grid of that cell size brings the neighbor query to roughly constant work per unit and moves the ceiling from hundreds into thousands.
