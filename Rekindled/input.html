Rekindled · Input Engineering

Input & Rebinding

Built the full input stack: Unity Input System integration across keyboard, Xbox, and PlayStation; live device detection that refreshes every UI prompt instantly; runtime key rebinding that persists to PlayerPrefs; and haptic feedback driven entirely from data.

Device Detection

The game needs to know which device the player is using at all times so every prompt, icon, and behavior matches their controller.

  • InputSchemeDetector (a static class) subscribes to OnActionTriggered on every action in the Player action map and reads the InputDevice type from each callback. When the scheme changes, it fires a static OnInputSchemeChanged event that all UI components listen to.
  • Three device classes are tracked independently: Keyboard/Mouse, Xbox (XInputController), and PlayStation (DualShock/DualSense). Prompt icons differ between Xbox and PlayStation so both are needed as separate schemes.
  • Gamepad trigger edge case: on some gamepads, performed and canceled fire on the same frame when a trigger is released slowly. A frame count guard on the cast handler prevents ghost spell executions from this hardware quirk.
  • Spells configured as CastOnPress fire immediately on button down instead of waiting for release. A separate guard prevents double execution if the action also fires performed on the same frame.
Live Prompt Refresh

Every UI element that displays a control label updates itself the moment the player switches devices, with no scene reload.

InputPromptUI

Subscribes to OnInputSchemeChanged and refreshes all displayed key labels instantly when the device changes.

NotificationPanel

Re-renders {prompt0} placeholders in notification text on scheme change, so tutorial prompts always show the correct button icon.

RebindButton

Refreshes its displayed binding label on scheme change, ensuring the rebind menu always shows the relevant control group for the active device.

Runtime Rebinding

Players can remap any action in the pause menu. Bindings persist across sessions and debug actions are excluded from the UI automatically.

  • RebindManager dynamically generates a row of RebindButton components from the InputActionAsset at runtime. No manual list to maintain when new actions are added.
  • Any action named "Look" and any action starting with "DEBUG" are skipped during row generation. Debug bindings live in the same action map but never surface in the rebind UI.
  • PerformInteractiveRebinding targets the binding index for the active control scheme group (Keyboard & Mouse vs Gamepad). During rebind the action is disabled, a "waiting for input" label shows, and the action reenables on complete or cancel.
  • Bindings are saved as JSON overrides in PlayerPrefs and loaded in Awake so custom bindings are active before the first frame. ResetToDefaults strips all overrides and deletes the key.

Why PlayerPrefs over a file? Steamworks cloud save syncs PlayerPrefs on supported platforms, so rebinds follow the player across machines without any extra code.

Haptics

Vibration patterns are fully data driven. Adding a new rumble effect for a new game event requires zero code.

  • VibrationManager disables Update at rest and reenables it only while a vibration is playing. No per frame cost when the gamepad is idle.
  • AnimationCurve profiles define left and right motor intensity over normalized time. Each VibrationSettings asset is a separate curve pair that designers author in the Inspector.
  • GameHaptics maps any GlobalMessages event (the project wide event bus) to a vibration profile via a List<VibrationMapping> in the Inspector. A static payloadTypeMap dictionary resolves the generic type needed for AddListener<T> at runtime without casting.
  • Bool typed events like OnCombineStateChanged support two profiles per mapping (true and false), so combine enter and combine exit rumble differently.
Sensitivity

Camera sensitivity updates live from the settings slider with no scene reload or settings apply button.

  • SensitivitySlider persists to PlayerPrefs on every slider change and broadcasts via MessagingService.OnSensitivityChanged (the project wide event bus). Initializes from the saved value on OnEnable, defaulting to the slider midpoint if no save exists.
  • AimPivotController receives OnSensitivityChanged and applies the multiplier to camera rotation immediately. The player can drag the slider and see the camera respond in real time.
