Spell Framework

Architected SpellBehavior, the abstract C# base class all six elemental spells inherit from. A five phase lifecycle shared across every ability, with zero per cast heap allocation and built in ground detection that handles slopes, walls, and obstacles.

Lifecycle and Caching

Six spells with different behavior need to share ground detection, indicator display, and cast state without duplicating any of it.

  • SpellBehavior is an abstract C# class exposing five override points: Initialize, OnBeginCast, OnUpdateCast, OnExecute, and OnCancel. Every spell implements only the phases it needs.
  • SpellHandler (the MonoBehaviour that owns spell execution on the player) caches one SpellBehavior instance per spell in a Dictionary<string, SpellBehavior> built at startup. Switching spells never allocates. The cached instance is activated and reset in place.
  • A pendingClear flag defers SpellHandler.Clear() to LateUpdate. Without it, a cast resolving in Update could fire OnExecute while the behavior clears its state on the same frame.
// five phases, subclasses override only what they need
public virtual void Initialize(SpellData data) { }
public virtual void OnBeginCast(SpellHandler caster) { }
public virtual void OnUpdateCast(SpellHandler caster) { }
public virtual bool OnExecute(SpellHandler caster) { }
public virtual void OnCancel() { }
Ground Detection

Zone spells need to know where the player is aiming in world space: on slopes, near walls, without heap allocation every frame.

  • A RaycastHit[5] array is stored as a field on SpellBehavior, allocated once at construction. Physics.RaycastNonAlloc fills it each frame with no heap allocation.
  • A best Y scoring loop selects the hit whose Y coordinate is closest to the player's feet, correctly prioritizing the floor when the ray also intersects an overhead ledge or wall.
  • ClampBehindObstacles fires a secondary ray from the player's waist toward the aimed ground point. If a solid obstacle is hit, the indicator snaps to just in front of it, keeping spells from clipping through walls.
  • If the aim ray hits nothing at all, a downward snap ray is cast from the flat forward max range point so the indicator never disappears when the player aims over a gap.
The Six Spells

Each spell subclass overrides only the phases it needs. Shared behavior like indicator placement and obstacle clamping runs automatically from SpellBehavior.

01 Homing Feather

Up to 8 pooled projectiles launched in a circular arc. Each feather has a phase offset staggering its bounce timing. Mana is deducted per feather at spawn time via delegate so the full cost is never charged upfront.

02 Dash

Three phase coroutine: startup, flight, recovery. A zero friction physics material during flight prevents catching on geometry edges. Camera damping lerps up during dash and back on recovery for a momentum feel.

03 Scorched Earth

Zone spell with a slope aligned indicator. The DamageZone it places triggers a kinematic elevator beneath it, letting the player use the spell as a platform to reach higher ground.

04 Ash Pillar

Zone spell that summons a pillar at the aimed ground point. Pooled pillar objects rising from below are guarded against a KillZone trigger at the level base that would destroy them before they surface.

05 Flame Shot

Direct fire projectile that executes immediately with no ground projection phase. Aim direction is computed from AimPivot (a shoulder mounted transform that drives camera and targeting) to the first ray hit.

06 Plume Cloud

Area denial projectile that spawns a persistent cloud on impact. Used alongside other spells to trigger elemental interactions on contact.

Per Spell Target Lock

Each spell configures the lock on system independently: range, cone width, on/off state. Fast spells and zone spells behave differently without any conditional logic inside the lock system.

  • AimPivotController (the component on the shoulder transform that owns camera aim and target lock) exposes SetActiveLockRange, SetLockOnEnabled, and SetActiveConeAngle. The Crosshair component calls all three when a spell is created or switched.
  • The cone check uses ClosestPoint on the collider surface rather than the center. Large enemies like the Golem register a lock as soon as the crosshair cone overlaps any part of their body, not just their pivot.
  • SetActiveLockRange is called with the spell's effective reach, so lock range always matches spell range and never extends farther than the spell can land.

Why not a single global lock range? Zone spells like Scorched Earth have a wider placement range than a direct projectile like Flame Shot. Tying lock range to spell range means players never lock onto an enemy they cannot actually hit with the selected spell.
