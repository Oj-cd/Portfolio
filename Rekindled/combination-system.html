Combination System

Built the elemental combination system designers author entirely from a ScriptableObject with no code changes needed to add new combos. A commutative dictionary lookup, time dilation, and mana rollback make the mechanic feel solid under the hood.

Lookup Design

Two elements in, one combo spell out. The lookup makes (A, B) and (B, A) equivalent so players do not need to care which element they selected first.

  • NormalizeKey sorts the two element enum values before hashing so (Fire, Ash) and (Ash, Fire) always map to the same tuple key.
  • BuildLookup runs at Awake and populates a Dictionary<(Elements, Elements), SpellData> from a SpellRegistry ScriptableObject (a Unity asset that holds the combo definitions). Adding a new combo is entirely designer driven: drag a SpellData asset into the registry, pick two elements, no code.
  • Combine.TryCombine returns a SpellData or null in a single dictionary lookup, feeding the result directly back into the spell creation pipeline.
// makes (A,B) and (B,A) hash to the same key
private (Elements, Elements) NormalizeKey(Elements a, Elements b)
    => a <= b ? (a, b) : (b, a);

public bool TryCombine(Elements a, Elements b, out SpellData result)
    => lookup.TryGetValue(NormalizeKey(a, b), out result);
Time Dilation and Mana

Entering combine mode slows time so the player can choose calmly. Mana should not regenerate during that pause, and a cancelled selection should cost nothing.

  • Time dilation is applied with Time.timeScale = combineTimeScale on combine entry and restored to 1 on exit or spell selection.
  • Mana regen suppression sets combineManaRegenMultiplier = 0 while in combine mode so the slowdown does not grant free regen.
  • Cast rollback accumulates manaPaidDuringCast during a charge and fully refunds it on cancel. Cancelling a half charged combo spell costs nothing.
  • Incremental deduction for multi projectile spells: the TryDeductMana delegate is passed into the behavior so each feather deducts independently at spawn. The player is never charged for feathers that never fired.

Why not charge the full mana cost upfront? Spells like Homing Feather can be cancelled mid cast. Charging upfront and refunding on cancel creates a visible mana flicker. Incremental deduction via delegate means only feathers that actually launched cost mana.

Combo Spells

Each combination produces a spell that neither source element has alone. The system ships with four combinations defined in the registry.

ElementsResultEffect
Fire + Ash Scorched Earth (enhanced) Larger zone radius and extended burn duration compared to the base spell.
Fire + Wind Flame Shot (enhanced) Projectile speed and damage boosted; ignition status applied on hit.
Ash + Wind Plume Cloud (enhanced) Cloud lingers longer and covers a wider area, increasing zone control.
Fire + Life Rebirth (enhanced) Healing output increased; faster cast time on the charge variant.
Stats Tracking

Every combine mode entry and per spell cast count is logged to PlayerProgressManager (the persistent save object) for the win screen summary.

  • An OnSpellCreated event fires whenever a spell is successfully combined. The win screen reads total combine entries from this counter.
  • Per spell cast counters increment each time OnExecute returns true. The win screen displays each spell's name and how many times it was cast across the entire run.
  • PlayerCharacter (the central player MonoBehaviour) subscribes to Combine.OnSpellCreated to trigger the element select animation through the animator, so the character visually reacts in the same frame the combo resolves.
