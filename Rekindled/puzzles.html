Puzzles & Interactables

Designed a shared PuzzleBase abstraction that two concrete puzzle types build on, wired every environmental interactable to the same restart system, and built a Scorched Earth platform mechanic that turns the player's own spell into an elevator.

PuzzleBase Architecture

All puzzles share state management and UnityEvent hooks so designers can connect completion effects, sounds, and gate unlocks without writing code.

  • PuzzleBase is an abstract C# class exposing CompletePuzzle, NotifyProgress, and ResetPuzzle virtual methods. Three UnityEvent hooks fire on each: onPuzzleCompleted, onPuzzleProgressed, onPuzzleReset.
  • All puzzles subscribe to OnGameRestarted via MessagingService (the project wide event bus) and call ResetPuzzle automatically. A canBeReset flag prevents permanent puzzles from resetting mid playthrough.
  • Completion broadcasts via MessagingService.OnPuzzleCompleted so the notification system can show a "puzzle complete" prompt without the puzzle knowing the notification system exists.

TorchPuzzle

Light all torches in any order. Tracks how many are lit and calls CompletePuzzle when the count reaches the total. Resets all torches and the count on restart.

TimedTorchPuzzle

Countdown starts on the first torch lit. If all torches are lit before time expires the puzzle completes; otherwise it resets. The coroutine is cancelled immediately on success.

Torch: Three Lighting Modes

Torches can be lit by spell hits, by proximity to a damage zone, or by direct script call. All three modes are independent so the same torch component can be configured differently in each puzzle.

  • Projectile hit: a DamageOnTrigger collider (a trigger component that detects player owned projectiles) on the torch fires a callback when a projectile enters. The torch lights and notifies its parent puzzle.
  • DamageZone proximity: each frame, OverlapSphereNonAlloc with a preallocated Collider[10] buffer checks for a Scorched Earth zone within range. If found, the torch lights. No per frame allocation.
  • LightPermanently(): a public method designers wire via UnityEvents when a trigger or cutscene should light the torch without any spell interaction.
  • Each mode is independently guarded so a torch already lit by proximity cannot be relit by a projectile hit, preventing double completion events.
Scorched Earth Elevator

The player can cast Scorched Earth below a platform to lift it. This creates a traversal mechanic where the player uses their own spell as an elevator.

  • DamageZone detection uses OverlapCapsuleNonAlloc spanning the bottom to top of the elevator shaft. If a Scorched Earth zone is found and the player is standing on the platform, the elevator ascends.
  • Enemy blocking: if an enemy is on the platform when the zone activates, the elevator shakes instead of rising and broadcasts OnElevatorEnemyBlocked. A grace duration prevents the block from toggling every frame when an enemy is walking across.
  • Carrier velocity injection: each FixedUpdate the platform's velocity is written into playerRigidbody.linearVelocity.y while the elevator ascends. Without this the player slides off the rising surface.
  • Seven state machine: WaitingAtTop, IntroDescending, Idle, Ascending, Holding, Descending, Blocked. All transitions are handled in a single FixedUpdate switch with no coroutines that can get stuck mid transition.

Why kinematic Rigidbody instead of a moving collider? A kinematic Rigidbody with Interpolate is the safest way to carry a physics character on a platform in Unity. Non kinematic platforms can fight the character controller's physics, causing jitter or the player falling through.

Other Interactables

Several environmental systems use the same restart pattern to stay repeatable across soft resets.

FireSpitter

Pooled trap. Projectile lifetime is derived from range / projectileSpeed so range is consistent at any speed. A closure captures the return to pool callback and cancels the lifetime coroutine on early hit.

FireSpitterGroup

Proximity manager for a set of FireSpitters. Spitters only run their shoot loop when the player is nearby. A state change guard fires StartShooting/StopShooting once on transition, not every frame.

DoorBehavior

Abstract base with SlideDoor (six configurable axes) and HingeDoor (pivot calculated from lossyScale and side enum) concrete types. Both play spatialized FMOD audio gated by camera distance.

PlumeCloudPuzzleRock

Physics prop that stores its start transform and resets position, velocity, and angular velocity on OnGameRestarted. Push puzzles are fully repeatable across restarts.
